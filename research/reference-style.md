## D source: repeated forms and variation

### Layout, naming, imports, and visibility

- The sampled D modules use a `module` declaration, blank line, imports, then implementation; braces are Allman-style and indentation is four spaces. Imports are commonly grouped into project/dependency imports and a later standard-library group. This is visible in an Autonom endpoint/store module, Intuit's provider and context modules, Selenium's driver and element modules, and Insurgent's GUI modules ([`autonom/source/daemon/agent/store.d:1-20`](../source/daemon/agent/store.d), [`Libraries/intuit/source/intuit/provider/openai.d:1-15`](../../Libraries/intuit/source/intuit/provider/openai.d), [`Libraries/intuit/source/intuit/context/package.d:1-15`](../../Libraries/intuit/source/intuit/context/package.d), [`Libraries/selenium/source/selenium/driver/package.d:1-34`](../../Libraries/selenium/source/selenium/driver/package.d), [`Insurgent/client/source/gui/game.d:1-17`](../../Insurgent/client/source/gui/game.d)).
- Class and struct names are PascalCase, ordinary functions and most runtime locals are camelCase, and descriptive constructed return values are often named `ret`. Autonom uses `Profile`, `ProfileStore`, `getProfile`, `canonicalName`, and `ret`; Intuit uses `Context`, `append`, and `ret`; Selenium uses `Driver`, `PrintOptions`, and `ret` ([`autonom/source/daemon/agent/profile.d:12-25`](../source/daemon/agent/profile.d), [`autonom/source/daemon/agent/store.d:68-90`](../source/daemon/agent/store.d), [`autonom/source/daemon/agent/store.d:97-110`](../source/daemon/agent/store.d), [`autonom/source/daemon/agent/store.d:239-248`](../source/daemon/agent/store.d), [`Libraries/intuit/source/intuit/context/package.d:14-41`](../../Libraries/intuit/source/intuit/context/package.d), [`Libraries/intuit/source/intuit/context/package.d:96-112`](../../Libraries/intuit/source/intuit/context/package.d), [`Libraries/selenium/source/selenium/driver/package.d:43-53`](../../Libraries/selenium/source/selenium/driver/package.d), [`Libraries/selenium/source/selenium/driver/print.d:17-37`](../../Libraries/selenium/source/selenium/driver/print.d), [`Libraries/selenium/source/selenium/bridge.d:381-408`](../../Libraries/selenium/source/selenium/bridge.d)).
- `ret` is a recurring local idiom, not the spelling of every return expression: `ProfileStore.list` builds and returns `ret`, while `validName` returns boolean expressions and `matchesPath` returns an expression directly ([`autonom/source/daemon/agent/store.d:239-261`](../source/daemon/agent/store.d), [`autonom/source/daemon/http.d:58-59`](../source/daemon/http.d)). Thus the source illustrates a tendency, not a literal implementation of the memory document's “return variables are always `ret`” text (`/home/cet/.codeium/windsurf/memories/global_rules.md:5-12`).
- Access sections (`private:`, `package(...)`, and `public:`) are used in all three D codebases, but not uniformly at every level. Autonom's `Profile` separates a private field, package-scoped binder, and public API; its `ProfileStore` similarly switches sections. Intuit's `OpenAI` groups private/protected/public members. Selenium combines public members with `package (selenium):` helpers in `Bridge` ([`autonom/source/daemon/agent/profile.d:25-55`](../source/daemon/agent/profile.d), [`autonom/source/daemon/agent/store.d:66-100`](../source/daemon/agent/store.d), [`Libraries/intuit/source/intuit/provider/openai.d:13-52`](../../Libraries/intuit/source/intuit/provider/openai.d), [`Libraries/selenium/source/selenium/bridge.d:24-60`](../../Libraries/selenium/source/selenium/bridge.d)).
- Private-field spelling is mixed in Autonom: `Profile._session` has a leading underscore, while `ProfileStore` fields such as `bridge`, `profiles`, and `assignments` do not; `Execution` has `_state` and `_timeout` beside `stopRequested` and `steerDepth`. Selenium's `PrintOptions` uses underscore-prefixed backing fields, and Insurgent uses `_pollId` alongside public `driver` and `match` fields ([`autonom/source/daemon/agent/profile.d:25-45`](../source/daemon/agent/profile.d), [`autonom/source/daemon/agent/store.d:97-110`](../source/daemon/agent/store.d), [`autonom/source/daemon/interop/execution.d:90-115`](../source/daemon/interop/execution.d), [`Libraries/selenium/source/selenium/driver/print.d:17-37`](../../Libraries/selenium/source/selenium/driver/print.d), [`Insurgent/client/source/gui/game.d:17-39`](../../Insurgent/client/source/gui/game.d)).
- Autonom uses both uppercase compile-time constants (`STEER_LIMIT`, `WAKES_FILE`, `MCP_PREFIX`) and PascalCase enum members (`Running`, `Succeeded`, `Start`); Insurgent also has lower-camel anonymous-enum symbols such as `gameUrl` and `pollFastMs`. ### Accessors, `@property`, and operation-shaped APIs

- A search of Autonom's tracked D source for `@property` found no declarations. Its `Profile` instead declares `Session session()` without the attribute; call sites in the same file and store use `profile.session` without parentheses. This is a property-like call shape without an explicit `@property` annotation in this sample ([`autonom/source/daemon/agent/profile.d:25-53`](../source/daemon/agent/profile.d), [`autonom/source/daemon/agent/store.d:109-110`](../source/daemon/agent/store.d)).
- Intuit's sampled API likewise has no explicit `@property` declaration: `IRouter` exposes getter/setter overloads for `active`, plus `ref` accessors for `name`, `tools`, and `context`; `OpenRouter` implements the overloads separately. Its `Context` instead uses action-named, chainable methods such as `append`, `system`, and `assistant`, returning `ref Context` ([`Libraries/intuit/source/intuit/router/package.d:19-64`](../../Libraries/intuit/source/intuit/router/package.d), [`Libraries/intuit/source/intuit/router/openrouter.d:90-94`](../../Libraries/intuit/source/intuit/router/openrouter.d), [`Libraries/intuit/source/intuit/context/package.d:22-62`](../../Libraries/intuit/source/intuit/context/package.d)).
- Selenium is the direct counterexample to a blanket no-`@property` description: `Driver.Timeouts` marks read and write accessors for `implicit`, `pageLoad`, and `script`; the setters issue remote `/timeouts` requests and update local browser state. Its `Window` template marks `position` and `rect` as properties while `handle`, `handles`, and `size` are ordinary methods and `close`, `maximize`, and `resize` are actions. `PrintOptions` properties validate numeric values in setters, and offline tests access them as fields (`options.pageWidth`, `options.scale`) ([`Libraries/selenium/source/selenium/driver/package.d:35-82`](../../Libraries/selenium/source/selenium/driver/package.d), [`Libraries/selenium/source/selenium/driver/package.d:517-590`](../../Libraries/selenium/source/selenium/driver/package.d), [`Libraries/selenium/source/selenium/driver/print.d:39-76`](../../Libraries/selenium/source/selenium/driver/print.d), [`Libraries/selenium/source/tests/webdriver/driver/print.d:11-21`](../../Libraries/selenium/source/tests/webdriver/driver/print.d)).
- These examples distinguish accessor-like reads from actions in real code: Autonom's `session` and Intuit's `active` can be read in property syntax, while `toJSON`, `clear`, and network or state-changing operations have explicit call parentheses; Selenium mixes explicitly annotated properties and ordinary methods within the same public API ([`autonom/source/daemon/agent/profile.d:39-53`](../source/daemon/agent/profile.d), [`Libraries/intuit/source/intuit/router/package.d:29-40`](../../Libraries/intuit/source/intuit/router/package.d), [`Libraries/intuit/source/intuit/context/package.d:104-117`](../../Libraries/intuit/source/intuit/context/package.d), [`Libraries/selenium/source/selenium/driver/package.d:517-587`](../../Libraries/selenium/source/selenium/driver/package.d)).

### Execution, API/data flow, and abstraction seams

- Autonom's executable entry module passes endpoint modules to `ServerinoMain!`; worker startup wires shared runtime objects and starts the scheduler. Endpoint functions are module-level declarations in domain files and reach state through `daemon.runtime`. For example, the profile endpoint calls `profileStore`, while `daemon.runtime.setup` constructs `Config`, `Devin`, stores, scheduler, policy, and permissions ([`autonom/source/daemon/app.d:19-34`](../source/daemon/app.d), [`autonom/source/daemon/server.d:59-75`](../source/daemon/server.d), [`autonom/source/daemon/agent/profile.d:12-23`](../source/daemon/agent/profile.d), [`autonom/source/daemon/runtime.d:13-36`](../source/daemon/runtime.d)).
- An Autonom session POST validates launch input and optional profile ownership before calling `bridge.start`; it responds with HTTP 202 and the execution JSON. The interop `Bridge` is an abstract base with an abstract `createSession` seam and shared process/execution helpers, and `Devin` is the concrete subclass. Execution owns a monitor thread and state; `save` atomically writes record JSON before and after monitor work ([`autonom/source/daemon/interop/devin/bridge.d:35-71`](../source/daemon/interop/devin/bridge.d), [`autonom/source/daemon/interop/devin/bridge.d:149-169`](../source/daemon/interop/devin/bridge.d), [`autonom/source/daemon/interop/bridge.d:409-450`](../source/daemon/interop/bridge.d), [`autonom/source/daemon/interop/execution.d:90-115`](../source/daemon/interop/execution.d), [`autonom/source/daemon/interop/execution.d:164-188`](../source/daemon/interop/execution.d), [`autonom/source/daemon/interop/execution.d:185-188,399-416`](../source/daemon/interop/execution.d), [`autonom/source/daemon/interop/execution.d:464-507`](../source/daemon/interop/execution.d)).
- Intuit is explicitly interface-oriented at provider/router boundaries: `IEndpoint` and `IRouter` define capabilities, and constrained free functions such as `completions` implement the request/tool-policy flow over those interfaces. `OpenAI` is a provider implementation, while `OpenRouter` maintains context, active model, model config, and catalog state. `Context` accumulates typed messages, optionally compacts after append, and returns itself for chaining ([`Libraries/intuit/source/intuit/provider/package.d:29-68`](../../Libraries/intuit/source/intuit/provider/package.d), [`Libraries/intuit/source/intuit/provider/package.d:92-181`](../../Libraries/intuit/source/intuit/provider/package.d), [`Libraries/intuit/source/intuit/router/package.d:19-80`](../../Libraries/intuit/source/intuit/router/package.d), [`Libraries/intuit/source/intuit/router/openrouter.d:19-69`](../../Libraries/intuit/source/intuit/router/openrouter.d), [`Libraries/intuit/source/intuit/context/package.d:22-62`](../../Libraries/intuit/source/intuit/context/package.d)).
- Selenium's `Bridge` is a concrete WebDriver-server/process and multi-session owner; `Driver` is a handle to one session. `Driver.start` serializes capabilities, asks the bridge to create a session, and binds the returned ID and negotiated browser. Its overloaded entry point creates a bridge from a browser-resolved executable. Thus the concrete split is server/session ownership rather than Intuit's provider/router interface pair ([`Libraries/selenium/source/selenium/bridge.d:17-24`](../../Libraries/selenium/source/selenium/bridge.d), [`Libraries/selenium/source/selenium/bridge.d:61-79`](../../Libraries/selenium/source/selenium/bridge.d), [`Libraries/selenium/source/selenium/driver/package.d:102-174`](../../Libraries/selenium/source/selenium/driver/package.d)).
- Autonom also uses a direct integration seam in policy: `Config` constructs an Intuit `OpenRouter` as `IRouter`, `Policy` uses `decisions`, and the route delegates to `policy.check`. The interface is present at the library boundary, but the daemon's configured router is concrete and currently rejects other router types in `createRouter` ([`autonom/source/daemon/config.d:118-168`](../source/daemon/config.d), [`autonom/source/daemon/policy/access.d:19-43`](../source/daemon/policy/access.d), [`autonom/source/daemon/policy/access.d:117-155`](../source/daemon/policy/access.d)).

### Error handling and tests

- Autonom uses typed input/conflict/backend exceptions and a central worker exception handler that maps them to HTTP 400/409/503, with a generic internal-server message for 500. The HTTP JSON reader translates parse failures into `InvalidInputException`; policy routes catch failures and return a denied result with 503. This is mixed with direct endpoint responses for cases such as a missing profile (404) ([`autonom/source/daemon/exception.d:1-18`](../source/daemon/exception.d), [`autonom/source/daemon/server.d:136-142`](../source/daemon/server.d), [`autonom/source/daemon/http.d:61-79`](../source/daemon/http.d), [`autonom/source/daemon/agent/profile.d:18-22`](../source/daemon/agent/profile.d), [`autonom/source/daemon/policy/access.d:39-43,117-155`](../source/daemon/policy/access.d)).
- Intuit's request helper turns curl timeouts and transport failures into specific exception types, then distinguishes authentication, rate-limit, other HTTP, and malformed-JSON responses. Selenium similarly uses domain-specific exceptions: `PrintOptions` rejects invalid setter values, and `Driver` translates a WebDriver timeout from script execution into `ScriptTimeoutException` ([`Libraries/intuit/source/intuit/provider/package.d:155-181`](../../Libraries/intuit/source/intuit/provider/package.d), [`Libraries/intuit/source/intuit/exception.d:7-47`](../../Libraries/intuit/source/intuit/exception.d), [`Libraries/selenium/source/selenium/driver/print.d:43-56`](../../Libraries/selenium/source/selenium/driver/print.d), [`Libraries/selenium/source/selenium/driver/package.d:475-500`](../../Libraries/selenium/source/selenium/driver/package.d)).

The launcher has a separate TypeScript `tests/unit` tree using `node:test` and `node:assert/strict`, with shared support helpers ([`autonom/source/tests/profile.d:1-35`](../source/tests/profile.d), [`autonom/source/tests/profile.d:148-177`](../source/tests/profile.d), [`autonom/source/tests/coord.d:1-16`](../source/tests/coord.d), [`autonom/source/tests/coord.d:40-65,150-185`](../source/tests/coord.d), [`autonom/source/tests/daemon.d:1-20`](../source/tests/daemon.d), [`autonom/source/tests/daemon.d:47-73`](../source/tests/daemon.d), [`autonom/source/launcher/tests/unit/center.ts:1-18`](../source/launcher/tests/unit/center.ts), [`autonom/source/launcher/tests/support.ts:1-21`](../source/launcher/tests/support.ts)).
- Intuit and Selenium D tests also use `@Name`/`unittest` and `unit_threaded`. Intuit's message tests assert serialized shapes; its OpenRouter catalog test is guarded by `version(integration)`. Selenium's print tests exercise property defaults, JSON shape, and validation-facing API behavior ([`Libraries/intuit/source/tests/context/message.d:1-59`](../../Libraries/intuit/source/tests/context/message.d), [`Libraries/intuit/source/tests/router/openrouter.d:1-30`](../../Libraries/intuit/source/tests/router/openrouter.d), [`Libraries/selenium/source/tests/webdriver/driver/print.d:1-52`](../../Libraries/selenium/source/tests/webdriver/driver/print.d)).
